# mosprom

Основное решение — ассистент-технолог для STE Slicer. Первый реализованный модуль — [анализатор STL](docs/STL_ANALYSIS.md), запускаемый отдельно на современном Python.

Локальный веб-чат первого этапа реализован в `src/backend` и `src/web`: ассистент в чате запускает работу, интерпретатор и проверяющий собирают единую карточку для второго этапа. Как устроены этапы 1–5, описано в [PIPELINE.md](docs/PIPELINE.md), контракт карточки 2.0 — в [TASK_CARD.md](docs/TASK_CARD.md), что из неё читает подбор параметров — в [stage1-contract.md](docs/stage1-contract.md). Прежнее [руководство реализации](docs/STAGE1_IMPLEMENTATION.md) устарело.

Ядро второго этапа, подбор параметров печати по готовой карточке, лежит в `src/backend/tuning`. Как выбирается каждый параметр, описано в [методике](docs/tuning/METHODOLOGY.md), принятые решения — в [DECISIONS.md](docs/tuning/DECISIONS.md).

**Портативная версия.** Установка: распаковать `AIAssistant-portable.zip` в `%APPDATA%\steslicer\7.10\plugins`, открыть STE Slicer и выбрать «AI Assistant → Открыть StereotechAI». Приложение работает одним процессом на SQLite, без Docker и Postgres. Подробности и сборка в [PORTABLE.md](docs/PORTABLE.md). Запуск из исходников: `uv sync --locked`, затем `uv run uvicorn src.backend.api.app:create_app --factory --port 8000` с заполненным `SESSION_SECRET` в `.env`. В браузер передаётся только одноразовый токен локальной сессии; ключ модели остаётся на сервере.

Подходит любой OpenAI-совместимый API. Адрес API, имя модели и ключ вводятся в окне чата. Они сохраняются в `DATA_DIR/model.json` и действуют со следующего вызова модели, без перезапуска. Пока в чате ничего не сохранено, действуют значения по умолчанию: в портативной сборке их передаёт плагин из «AI Assistant → Настройки», при запуске из исходников это `QWEN_BASE_URL`, `QWEN_MODEL` и `QWEN_API_KEY` из `.env`.

После карточки конвейер подбирает параметры, проверяет их, нарезает в STE Slicer через плагин AI Assistant и проверяет G-code; итог это `project.3mf` и `result.gcode`. Как это устроено и как проверить на Windows с настоящим слайсером, описано в [PIPELINE.md](docs/PIPELINE.md). Без слайсера (например на Mac) его заменяет `scripts/fake_ste_slicer.py`.

Перед работой прочитайте [CONTRIBUTING.md](CONTRIBUTING.md). Реализованные возможности отслеживаем в [реестре фич](docs/FEATURES.md).

[Решения по первому этапу](docs/STAGE1_DESIGN.md) фиксируют согласованное поведение и ограничения проектирования, включая **KB-001: база знаний первой версии покрывает семь тестовых деталей, доступные материалы и основной профиль принтера**. При расширении набора задач это ограничение требуется пересмотреть.

[Вики Фёдора](research/wiki/ABOUT.md) — справочные материалы и исследование, а не основное решение проекта.

[Текущая концепция команды](research/wiki/concept.html): роли, пять этапов обработки запроса и открытые вопросы.

Python-зависимости управляются через `uv`: `uv sync --locked`, затем `uv run --locked pytest`. Версии закреплены в `uv.lock`, рабочие зависимости и группа `dev` описаны в `pyproject.toml`. PDF рендерятся постранично и читаются мультимодальной моделью; отдельный OCR не используется.
