# AI Assistant для STE Slicer

Ассистент-технолог для гибридного принтера Stereotech Hybrid 530. Пользователь пишет в чат, что за деталь и зачем она нужна, прикладывает модель STL и техническое задание. Ассистент разбирает задание, при необходимости задаёт уточняющие вопросы, подбирает режим печати (3D или 5D), материал и настройки, нарезает модель в STE Slicer и проверяет G-code. На выходе готовый проект слайсера, G-code и отчёт, почему выбрано именно так.

Решение ставится как плагин STE Slicer одним архивом. Python, база и интерфейс уже внутри, Docker и отдельные серверы не нужны.

## Установка

Нужен Windows и STE Slicer 7.10.12.

1. Скачайте `AIAssistant-portable.zip` из [последнего релиза](../../releases/latest) и закройте STE Slicer.
2. Распакуйте архив так, чтобы получилась папка `%APPDATA%\steslicer\7.10\plugins\AIAssistant`. Папку конфигурации открывает пункт «Справка → Показать папку конфигурации», внутри подпапка `plugins`.
3. Запустите слайсер, в меню «AI Assistant → Настройки» укажите адрес OpenAI-совместимого API, модель и ключ. Их можно ввести и позже, в окне чата.
4. «AI Assistant → Открыть StereotechAI» откроет чат в браузере. Первый запуск занимает до минуты, пока создаётся база и загружаются знания.

Режимы 5D режет отдельная программа слайсера, ей нужна лицензия на компьютер. Начните в слайсере нарезку любой модели в 5D, скопируйте код из окна ATSS, получите по нему файл `steslicer_license.reg` на странице кейса (вкладка STE Slicer), запустите его и перезапустите слайсер. Лицензия действует 10 дней.

## Как пользоваться

1. В чате опишите деталь своими словами и приложите модель STL. Техническое задание можно приложить файлом (PDF, DOCX, TXT, MD) или фотографией.
2. Ассистент показывает ход работы по этапам. Если данных не хватает или источники противоречат друг другу, он задаёт вопросы в отдельном окне. На вопрос можно ответить «не знаю», тогда ассистент примет обоснованное допущение.
3. Когда проект готов, в чате появляется итоговый отчёт: что взято из файлов, какие допущения сделаны, какие параметры выбраны и почему, время печати и расход материала.
4. В том же чате можно спросить, почему выбран материал или режим, попросить поправить проект или прислать следующую деталь.

## Что получается

Каждый расчёт сохраняется в свою папку `Documents\STE_AIAssistant\Результаты\<деталь>`.

| Файл | Что это |
| --- | --- |
| `project.3mf` | проект STE Slicer со всеми настройками, открывается в слайсере |
| `result.gcode` | G-code этого проекта |
| `chat_01.png` | переписка по проекту: вопросы ассистента, ответы, итоговый отчёт; длинная переписка продолжается в `chat_02.png` и дальше |
| `report.md` | итоговый отчёт текстом |

Повторный расчёт той же детали получает папку с номером, например `Шестерня (2)`, и прежний результат не меняется.

## Как устроено

Работа идёт пятью этапами.

1. **Разбор задания.** Ассистент ведёт разговор и запускает работу. Интерпретатор читает сообщения, документы и изображения, а код тем временем анализирует сетку STL: габариты, дефекты, нависания, оси вращения, сечения. Проверяющий сверяет задание с моделью, ищет противоречия и оставляет только нужные вопросы. Итог этапа это карточка задания с требованиями в кодах общего словаря. Подробно в [PIPELINE.md](docs/PIPELINE.md) и [TASK_CARD.md](docs/TASK_CARD.md).
2. **Подбор параметров.** Детерминированные правила, у каждого решения указан источник: режим 3D или 5D по классу детали и геометрии, ориентация, материал по требованиям и паспортам, профиль, стенки, заполнение, поддержки, адгезия. Методика в [METHODOLOGY.md](docs/tuning/METHODOLOGY.md), принятые решения в [DECISIONS.md](docs/tuning/DECISIONS.md).
3. **Проверка набора.** Набор сверяется с каталогом слайсера и требованиями карточки. При замечаниях подбор повторяется ещё раз.
4. **Нарезка.** Плагин AI Assistant применяет набор в STE Slicer через MCP-инструменты, режет модель и сохраняет G-code и проект. Подробно в [SLICING_STAGES_4_5.md](docs/SLICING_STAGES_4_5.md).
5. **Проверка G-code.** Режим печати, температуры, границы стола и время печати сверяются с набором. Если модель выходит за стол, подбор повторяется.

Языковая модель работает только на первом этапе и в разговоре. Параметры печати выбирает код, поэтому одна и та же карточка всегда даёт один и тот же набор.

Устройство портативной версии описано в [PORTABLE.md](docs/PORTABLE.md), реализованные возможности и их проверки перечислены в [FEATURES.md](docs/FEATURES.md).

## Запуск из исходников

Нужны Python 3.11, [uv](https://docs.astral.sh/uv/) и Node.js 20 или новее.

```sh
uv sync --locked
npm ci --prefix src/web && npm run build --prefix src/web
python scripts/bootstrap.py
uv run uvicorn src.backend.api.app:create_app --factory --port 8000
```

`bootstrap.py` создаёт `.env` с секретом сессии и печатает ссылку входа в чат. Ключ модели можно указать в `.env` (`QWEN_API_KEY`) или ввести в окне чата. Без STE Slicer, например на macOS, слайсер заменяет `scripts/fake_ste_slicer.py`. Портативный архив собирает `uv run python scripts/build_portable.py`.

## Проверки

```sh
uv run --locked python scripts/run_tests.py
```

Скрипт запускает pytest с покрытием, ruff, mypy, unit-тесты интерфейса и браузерные сценарии Playwright на собственном стенде с заглушками модели и слайсера. Прогон через настоящую модель на деталях организаторов делает `scripts/eval_pipeline.py`, сравнение двух прогонов `scripts/compare_results.py`.

## Структура

```text
src/backend/   приложение: агенты, подбор параметров, проверки, нарезка, API
src/web/       интерфейс чата
src/plugin/    плагин STE Slicer (Python 3.5)
knowledge/     каталог слайсера, словарь требований, база материалов
docs/          описание этапов, контрактов и решений
scripts/       сборка, стенды, прогоны
tests/         unit, интеграционные и сквозные тесты
research/      исследование рынка и готовых решений
```
