## Расхождения вики с заданием

Видео показывает промышленный контекст срочной замены детали и сложность настройки слайсера; задача сформулирована через плагин, MCP и ИИ-агента. На экране есть пример рабочего колеса с условиями химической среды и нагрева. Это поддерживает фокус на требованиях к эксплуатации. Точные форматы, ограничения и сдачу определяет письменное задание; пример из видео не заменяет отдельное ТЗ выданного колеса Wilo, где указана другая среда.

| Вики | Факт официального задания | Следствие для плана |
|---|---|---|
| Широкая цепочка до парка и мониторинга | Проверяется плагин в STE Slicer и файлы по моделям | Исключить парк и мониторинг из конкурсного объёма |
| 5D отмечено дополнительным направлением | Выбор 3D/5D входит в основную проверку; три примера помечены 5D | Проверять 5D в первый день |
| Выбор между Orca, Prusa, Cura | Задан STE Slicer, глубокий форк Cura 3.6 | Использовать штатные API и движки выданной версии |
| Готовый Python MCP SDK — кандидат основы | В задании требуется совместимость Python 3.5, SDK внутри не запускается | Реализовать необходимый объём JSON-RPC без современного SDK |
| Фото как источник генерации модели | Обязательны изображения и 3D-модели как входы; генерация CAD не требуется | Использовать фото для понимания задачи и уточнений |

Презентация говорит об интеграции чатбота в программу. Полное техническое задание конкретизирует это как SPA в системном браузере, которую открывает локальный сервер плагина. Не тратить время на встраивание браузерного движка в старый PyQt5 без необходимости.

## Выводы из исходников

Пути ниже относительны корню `STE-Slicer-master` внутри выданного архива. Это статическая проверка кода; запуск Windows-дистрибутива в рамках исследования не выполнялся.

- `resources/definitions/fdmprinter.def.json`: реальный ключ режима — `printing_mode`; значения `classic`, `cylindrical`, `cylindrical_full` соответствуют 3D, 5D Spiral и 5D. В исходниках есть дополнительные режимы, но задание их не разрешает.
- `resources/definitions/hte530v5.2.4.def.json`: профиль `Stereotech Hybrid 530 V5.2.4`, два экструдера. Материалы и параметры нужно читать с учётом выбранного экструдера.
- `steslicer/BackendManager/BackendManager.py`: переключение backend связано с изменением `printing_mode`. Нельзя считать изменение названия режима в чате достаточным.
- `steslicer/SteSlicerApplication.py`: `getBackend()` возвращает текущий backend. Для актуального состояния ориентироваться на фактический активный режим.
- `plugins/3MFWriter/ThreeMFWorkspaceWriter.py`: полный проект сохраняет глобальный стек, контейнеры, стеки экструдеров и часть настроек. Обычный mesh writer не заменяет workspace writer для сдачи проекта.
- `steslicer/Settings/MachineManager.py`: существуют методы выбора материала и качества. Сигнатуры и ID проверять по выданному коду, не угадывать по современной Cura.
- `resources/materials/`: доступны семейства Stereotech Enduse, Fiberpart, Sealant, описания и настройки печати. Например, XML материала содержит краткое описание и температуры, но не полный набор механических и химических характеристик из ТЗ.
- `resources/definitions/steprinter530_v5.2.4.def.json`: рабочая область зависит от режима. Проверка геометрии должна учитывать текущую конфигурацию.
- В Uranium `UM/Application.py` есть `callLater`; официальное задание требует выполнять изменения сцены и настроек в главном потоке Qt.

Самые дорогие ошибки интеграции: зависимость от неподдерживаемого Python; изменение Qt-объектов из потока HTTP; работа со старым backend после смены режима; экспорт только геометрии; экспорт устаревшего G-code после нового изменения сцены; отсутствие активированной 5D-лицензии.

## Проверка входных моделей

Габариты ниже вычислены по координатам исходных бинарных STL без преобразований. STL не хранит единицы; считать числа миллиметрами можно после подтверждения импорта в STE Slicer. Это не проверка печатаемости, герметичности или оптимальной ориентации.

| Деталь | Метка режима в папке | Число треугольников | Габариты по осям исходного файла |
|---|---|---:|---|
| Шестерня | 3D | 24 920 | 33,10 × 10,10 × 33,10 |
| Колесо конвейера | 5D | 2 428 | 59,00 × 25,00 × 58,99 |
| Пыльник ШРУСа | 3D | 338 526 | 111,00 × 102,99 × 102,98 |
| Фигурка | Не указана | 564 696 | 103,29 × 128,75 × 149,98 |
| Колесо Wilo | 5D | 73 604 | 134,64 × 50,74 × 134,65 |
| Крыльчатка двигателя | 3D | 11 252 | 169,00 × 22,00 × 169,00 |
| Ось Krones | 5D | 7 068 | 61,70 × 23,50 × 40,50 |

Фигурка и пыльник полезны для проверки отзывчивости интерфейса и загрузки больших сеток. Пыльник — хороший контрпример правилу «осесимметричная деталь означает 5D». Для фигурки требуется партия 15 штук; формат представления партии стоит уточнить у эксперта.

ТЗ рабочего колеса Wilo требует одновременно низкого водопоглощения, ограниченной плотности, высокой жёсткости, термостойкости и работы в горячем щелочном теплоносителе. Нельзя подобрать материал только по названию полимера. Требуются паспорт конкретной марки, сопоставление обязательных ограничений и обсуждение компромиссов с экспертом.

## Что остаётся проверить при разработке

- Установка и работа плагина в Windows STE Slicer 7.10.12, фактический Python и доступные модули.
- Активация, ручной и программный слайсинг всех трёх разрешённых режимов.
- Состав материалов и профилей именно установленного дистрибутива.
- Поведение выданной модели LLM: tool calling, изображения, ошибки и задержки. API в ходе подготовки концепции не вызывался.
- Способ сравнения с закрытыми эталонами, допуски, веса критериев и допустимость альтернативных материалов.
- Регламент и индивидуальные слоты команды в личном кабинете.

Результаты плагина, точность подбора, скорость и успешность печати ещё не измерены: текущий репозиторий на момент начала исследования содержал только README. Документы задают план разработки, а не отчёт о работающем прототипе.
