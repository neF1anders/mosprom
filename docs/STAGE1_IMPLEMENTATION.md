# Локальный первый этап

## Запуск

Нужны Docker Compose и Python для генерации ссылки запуска. Node и системный Tesseract на машине пользователя не требуются.

```bash
python3 scripts/bootstrap.py
# В .env задайте QWEN_API_KEY. Не добавляйте .env в Git.
docker compose up --build -d
docker compose exec api alembic upgrade head
python3 scripts/bootstrap.py
```

Откройте последнюю выведенную ссылку. Токен однократный, действует 10 минут; после обмена браузер получает HttpOnly SameSite-cookie. Обновление страницы сохраняет чат. Порт 8000 опубликован только на 127.0.0.1. PostgreSQL 18 и вложения находятся в постоянных томах. `docker compose down` сохраняет данные; `down -v` удаляет их.

Без ключа интерфейс открывается, но интерпретация моделью сообщает об отсутствии настройки. Нет автоматической подмены Qwen заглушкой. Тестовый API используется только в compose.test.yaml.

## Структура

- `src/backend/domain`: Pydantic-контракты, каталог gates, источники, нормализация, переходы состояний. Нет HTTP, БД и файловых операций.
- `src/backend/ports`: интерфейсы UoW, репозиториев, файлов, модели и передачи карточки.
- `src/backend/services`: отдельные сценарии команд, загрузки, подготовки источников, геометрии, библиотеки, извлечения и pipeline.
- `src/backend/infrastructure`: PostgreSQL-реализации, HTTPX Qwen, файловое хранилище, изолированные процессы документов/STL.
- `src/backend/api/routes`: отдельные файлы маршрутов по предметной области. Зависимости собирает `container.py`.
- `src/backend/worker.py`: получение lease, heartbeat и вызов общего Pipeline. Бизнес-правила не дублируются.
- `src/web`: React/TypeScript/CSS Modules; собранную статику раздаёт FastAPI.

UoW скрывает AsyncSession. Репозитории не делают commit. Изменение задания, квитанция команды, событие и постановка в очередь фиксируются атомарно. Внешний API и процессы вызываются вне транзакций. Для получения работы используются `FOR UPDATE SKIP LOCKED`, lease 30 секунд и heartbeat каждые 5 секунд. Устаревший владелец не может сохранить финальный результат.

## HTTP и контракты

OpenAPI доступен на `/api/v1/openapi.json`, маршруты — `/api/v1`. Для изменяющих команд обязателен UUID `request_id`; ответы/конфликты требуют `expected_revision`. Повтор с тем же ключом и содержимым возвращает прежний результат; другое содержимое с тем же ключом и устаревшая версия дают 409.

Основные ресурсы: `/jobs`, `/jobs/{id}`, `/jobs/{id}/attachments`, `/messages`, `/answers`, `/conflicts`, `/control/{stop|resume|retry}`, `/events`, `/card`, `/artifacts/{id}`. Пути после `{id}` относятся к заданию. Список заданий и история используют курсоры. SSE поддерживает Last-Event-ID и `after`; клиент удаляет дубли событий. Файл другого задания через его URL недоступен.

`TaskCard` из `domain/models.py` — транспортная схема версии 1.1 ([JSON Schema](task-card-v1.1.schema.json), [контракт передачи](TASK_CARD.md)). В карточке есть требования со значением/единицей/условиями/источниками, вопросы, решения конфликтов, геометрия, допущения, неизвестные, допустимые и заблокированные действия, версии правил и источников. `ready/preliminary/blocked` не заменяют техническое состояние задания.

При смене текста, единиц или активного STL создаётся новая revision. Запрос статуса её не меняет. Экспорт устаревшей карточки запрещён. Остановка применяется на безопасной границе: текущее внешнее действие может закончиться, следующее не запускается.

## Harness и ограничения

Восемь обращений к модели за автоматическую итерацию; число пользовательских раундов не ограничено. Доступны только `analyze_stl` и `search_knowledge`. Валидация аргументов проверяет принадлежность и актуальность STL, подтверждённые единицы и разрешённое имя. Повтор одинаковой операции без прогресса останавливается. Обязательный анализ геометрии запускает код независимо от желания модели.

Временные ошибки повторяются максимум два раза после исходной попытки. Ошибки авторизации/неверного запроса не повторяются. Ошибка схемы получает одну попытку исправления. Кеш учитывает содержимое, аргументы, версию анализатора и контекст извлечения; успешный инструмент не выполняется заново при сетевом повторе модели. Тексты документов считаются данными. В журнале показываются действия и источники, внутренний reasoning модели не сохраняется.

Начальные верхние ограничения: STL 256 MiB/2 млн граней/120 секунд; PDF 25 MiB/50 страниц/30 секунд на страницу; DOCX 25 MiB/100 MiB распакованного содержимого; JPG/PNG 20 MiB/25 мегапикселей; 20 сопроводительных файлов. `LIMITS__PDF_PAGES`, `LIMITS__STL_MIB` и остальные поля `InputLimits` позволяют уменьшать ограничения; повышение принятых верхних границ требует изменения и проверки кода. OBJ и 3MF не поддерживаются.

PDF со смешанным содержимым проходит текстовое извлечение и OCR страниц с изображениями. Локальный OCR использует rus+eng. PDFium, OCR и Trimesh выполняются в отдельных процессах. Сохраняются независимые результаты и контрольные точки; ошибка PNG/сечений/лучей не аннулирует габариты. Самопересечения не считаются проверенными, normal chord не выдаётся за минимальную толщину. Физический объём не подтверждается одним признаком watertight; масса печати не вычисляется как плотность × объём оболочки.

## Библиотека KB-001

`knowledge/catalog.json`: 26 карточек плотности из профилей Stereotech, основной профиль Hybrid 530 V5.2.4, правило покрытия и семь карточек исходных примеров. Это справочные значения профилей, а не паспортные измерения. Метод и температура измерения плотности в профилях не указаны. Требования примеров имеют scope=example и не являются свойствами материалов.

`knowledge/sources` содержит исходные профили и Markdown-тексты семи ТЗ с SHA-256 DOCX. Повторная сборка:

```bash
python scripts/build_knowledge.py /path/to/STE-Slicer --examples /path/to/examples
python scripts/import_knowledge.py
```

Поиск использует нормализованные проверенные алиасы, точную марку/свойство, условия и PostgreSQL FTS с русской конфигурацией. Не более пяти записей, следующий offset возвращается явно. Несовпадение условий, семейство или разные значения возвращают `ambiguous`; отсутствие — `not_found`. Интернет-поиска в runtime нет. Внешнему Qwen передаются текст/изображения из контекста: приложение на localhost не означает полностью локальную обработку.

## Интеграция следующего этапа

По умолчанию HANDOFF_URL пустой. UI честно сообщает «Карточка подготовлена, следующий этап не подключён» и предоставляет JSON. В `card.stl_analysis` сервер встраивает весь JSON анализатора без сокращений. Сохранённая карточка, экспорт и тело передачи идентичны; отдельное скачивание геометрического отчёта следующему этапу не требуется. При настройке URL отправляется POST `{idempotency_key, card}`, заголовок `Idempotency-Key: job_id:revision`. Приёмник обязан дедуплицировать ключ и проверять актуальность revision перед запуском зависимой работы; одной дедупликации недостаточно для изменения задания во время доставки. Тестовый приёмник — `tests/handoff_server.py`.

Интеграция с STE Slicer и установка без Docker не входят в эту поставку. Открытие в отдельном WebView возможно через одноразовую ссылку и тот же origin; iframe запрещён CSP до согласования origin плагина. Создание проекта слайсера и G-code не реализовано и явно заблокировано каталогом первого этапа.

## Проверки

```bash
docker compose -f compose.test.yaml up --build --abort-on-container-exit --exit-code-from tests
```

Изолированное окружение содержит настоящий PostgreSQL, API, worker, воспроизводимый тестовый Qwen и Chromium. Оно генерирует фикстуры, применяет миграции, выполняет pytest с порогом покрытия 80%, Ruff, mypy, Vitest и браузерные E2E. Браузерный отчёт сохраняется в `artifacts/playwright-report`; подробности — `docs/STAGE1_ACCEPTANCE.md`.

Для отдельных запусков установите `requirements-dev.txt`, выполните `npm --prefix src/web ci`, задайте TEST_DATABASE_URL к отдельной тестовой БД и запустите команды из спецификации. Live smoke `python scripts/smoke_qwen.py` использует реальный ключ и синтетические данные; не входит в воспроизводимый offline-прогон.
