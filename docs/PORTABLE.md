# Портативная версия

Ветка `feat/portable`. Установка: распаковать архив в папку плагинов слайсера и открыть слайсер. Docker, Postgres и отдельные запуски не нужны.

## Установка для жюри

1. Скачайте `AIAssistant-portable.zip` и закройте STE Slicer.
2. Распакуйте архив так, чтобы получилась папка `%APPDATA%\steslicer\7.10\plugins\AIAssistant` (путь открывается через «Справка → Показать папку конфигурации», подпапка `plugins`).
3. Запустите STE Slicer, выберите «AI Assistant → Настройки», введите адрес API, ключ и модель.
4. Выберите «AI Assistant → Открыть StereotechAI». В браузере откроется чат.

Первый запуск занимает до минуты: создаётся база и загружаются знания. Если чат не открылся, причину смотрите в `AIAssistant\runtime\data\logs\backend.log`.

## Как устроено

Слайсер встраивает Python 3.5, а наше приложение требует 3.11. Поэтому плагин (3.5) запускает рядом наше приложение на своём Python 3.11, лежащем в той же папке.

```
AIAssistant\
  plugin.json, AIAssistant.py, agent\     плагин, Python 3.5, только стандартная библиотека
  runtime\
    python\                               портативный Python 3.11 с установленными пакетами
    app\                                  src\backend, src\mesh_analysis.py, knowledge\, src\web\dist
    data\                                 app.db (SQLite), загрузки, артефакты, logs\
```

1. Слайсер загружает плагин. По пункту меню «Открыть StereotechAI» `agent/sidecar.py` выбирает свободный порт, создаёт секрет сессии и запускает `runtime\python\python.exe -m uvicorn src.backend.api.app:create_app --factory`.
2. При старте приложение создаёт таблицы, загружает `knowledge/catalog.json`, запускает исполнитель очереди и отвечает на `GET /api/v1/health`.
3. Плагин строит одноразовую ссылку и открывает браузер. Интерфейс тот же, что и в основной версии.
4. Приложение само вызывает плагин по `server.json` (слайсер на этом же компьютере), файлы обмениваются через `Documents\STE_AIAssistant`.
5. Приложение следит за процессом слайсера (`PARENT_PID`) и завершается вместе с ним.

Ключ и модель берутся из настроек плагина один раз при запуске приложения. После смены ключа перезапустите слайсер.

## Отличия от основной версии

- SQLite (режим WAL) вместо Postgres. Каждая транзакция сразу берёт блокировку записи, поэтому параллельные чаты ждут друг друга, а не падают.
- Очередь внутри процесса вместо Procrastinate. Строка в `task_queue` пишется в той же транзакции, что и состояние задачи. На одно задание идёт один этап за раз, всего не больше `WORKER_CONCURRENCY` (по умолчанию 4). Работа, прерванная закрытием слайсера, при следующем старте запускается заново: обработчики идемпотентны.
- События чата передаются через объект в памяти, а не через `LISTEN/NOTIFY`.
- Миграций нет: база всегда создаётся при первом запуске.
- Превью STL рисуется Pillow, а не matplotlib. Картинка та же по смыслу: три проекции с затенением.
- Docker и compose-файлы остались только в `main`.

## Сборка

```
uv run python scripts/build_portable.py            # собирает фронтенд и архив
uv run python scripts/build_portable.py --skip-web # использовать готовый src/web/dist
```

Скрипт скачивает Python 3.11 embeddable и колёса под `win_amd64` (нужен интернет на машине сборки, не у жюри), проверяет синтаксис плагина под Python 3.5 и целостность архива. Результат: `dist/AIAssistant-portable.zip`.

На Mac, если Python не видит сертификаты, задайте `SSL_CERT_FILE` из `certifi` (см. команду в истории сборки).

## Запуск из исходников без плагина

```
cp .env.example .env     # заполнить QWEN_API_KEY и SESSION_SECRET
uv sync --locked
uv run uvicorn src.backend.api.app:create_app --factory --port 8000
```
