# Анализ STL

`src/mesh_analysis.py` — самостоятельный CLI и функция `analyze_stl(path, ...)` для первого этапа ассистента. Требуется Python 3.11+ для закреплённого набора зависимостей. Код не рассчитан на Python 3.5 внутри STE Slicer. Согласование вспомогательного процесса с организаторами остаётся отдельным вопросом.

## Запуск

```sh
python3.11 -m venv .venv
.venv/bin/python -m pip install -r requirements-stl.txt
.venv/bin/python src/mesh_analysis.py /path/to/model.stl --output-dir artifacts/stl-analysis --preview
```

На Windows используется `.venv\Scripts\python.exe`. Можно передать несколько файлов или папок; папки обходятся рекурсивно, расширение STL проверяется без учёта регистра.

По умолчанию масштаб **неизвестен**. Если пользователь или проект достоверно задаёт миллиметры, добавьте `--units mm`. `--units cm|m|inch` переводит координаты в миллиметры. Сам STL не подтверждает единицы; источник всегда записан как указание вызывающей стороны. PNG показывает исходные координаты файла.

Каждая модель получает JSON с полными данными и краткий Markdown. `--preview` добавляет PNG с тремя ортографическими видами без OpenGL. `index.json` сопоставляет исходные пути и отчёты. В именах отчётов используются номер и хеш пути, поэтому одинаковые имена файлов из разных папок не сталкиваются.

Код завершения: `0` — все модели прошли перечисленные проверки; `1` — обнаружены дефекты или ошибки хотя бы у одного файла; `2` — ошибка аргументов. Найденные дефекты не мешают получить доступные измерения остальных моделей.

## Состав отчёта

- SHA-256, размер, бинарный/ASCII STL, версии Trimesh и NumPy.
- Число граней, вершин, рёбер; точное объединение совпадающих вершин без округления. Исходник не перезаписывается; грани не удаляются и не исправляются. При разделении оболочек автоматическое заполнение дыр явно отключено.
- Вырожденные и повторные грани, граничные и неманифолдные рёбра, согласованность обхода, замкнутость, знаки объёма оболочек. Порог вырожденности зависит от размера модели и записывается в отчёт.
- Связные оболочки по смежности граней, их площади, габариты, характеристика Эйлера и условный род замкнутых ориентированных оболочек.
- Габариты XYZ, площадь, центроид поверхности, статистика длин рёбер, площадей и минимальных углов треугольников, углов между соседними гранями.
- Условный объём, центр масс и тензор инерции при единичной плотности только для одной замкнутой, ориентированной оболочки без выявленных дефектов. Это геометрические свойства, а не масса напечатанной детали с заполнением.
- Выпуклая оболочка и отношение объёма к её объёму. PCA по вершинам: оси и размеры в полученной системе; это не минимальный ориентированный параллелепипед и не распознавание оси вращения.
- Девять сечений: на 25%, 50% и 75% габарита вдоль каждой оси; координата, количество замкнутых контуров и длина сечения.
- Выборочные внутренние хорды по нормали: 128 точек поверхности с вероятностью, пропорциональной площади, фиксированный seed. `--samples 0` отключает; максимум 4096.

## Границы достоверности

`checks_passed` означает отсутствие дефектов **в перечисленных проверках**, а не полную геометрическую валидность или возможность изготовления.

Самопересечения, взаимные пересечения и вложенность оболочек, манифолдность в вершинах не проверяются. При нескольких оболочках общий физический объём не выдаётся: вложенная оболочка может быть полостью, а пересекающиеся тела требуют булевой обработки. Объём одной оболочки также условен, пока не проверены самопересечения.

Хорды — приблизительная характеристика расстояния до следующей поверхности вдоль внутренней нормали. Они **не являются доказанной минимальной толщиной стенки**: выборка может пропустить маленький тонкий участок, а вогнутости и полости влияют на длину. Для открытых/дефектных/многокомпонентных сеток этот анализ не запускается.

Инструмент не определяет материал, нагрузки, допуски, посадки, функциональные поверхности, прочность, режим 3D/5D или требуемые поддержки. Не исправляет модель и не запускает слайсинг.

## Ограничения ресурсов

По умолчанию файл ограничен 256 MiB и 2 000 000 треугольников. CLI запускает каждую модель отдельным дочерним процессом и прерывает её через 120 секунд. Пределы регулируются `--max-bytes`, `--max-faces`, `--timeout`. Ограничения памяти ОС не устанавливаются; отдельный процесс и лимиты входа не заменяют sandbox для враждебных файлов. При прямом вызове функции таймаут должен обеспечивать вызывающий код.

## Проверки

```sh
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pytest --cov=src --cov-report=term-missing --cov-fail-under=80
```

Тесты содержат аналитические геометрические примеры, испорченные сетки и сквозной запуск CLI. CI выполняет тот же набор на Ubuntu и Windows. Локальный прогон на macOS сам по себе не подтверждает Windows-интеграцию со STE Slicer.
