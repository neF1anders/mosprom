# Единая карточка этапа 1 → этап 2

Транспортный контракт `TaskCard`, версия **1.1**. Машиночитаемая схема: [task-card-v1.1.schema.json](task-card-v1.1.schema.json). Endpoint `GET /api/v1/jobs/{job_id}/card` возвращает полную текущую карточку. Сохранённая в PostgreSQL карточка, экспорт из этого endpoint и `card` в handoff содержат одинаковые данные.

## Передача

При наличии `HANDOFF_URL` и допустимости подбора параметров сервер отправляет один POST:

```json
{
  "idempotency_key": "job_uuid:revision",
  "card": {
    "schema_version": "1.1",
    "revision": 12,
    "purpose": "Корпус подшипника",
    "requirements": [],
    "answers": {"geometry.units": "mm"},
    "resolutions": {},
    "geometry": {},
    "stl_analysis": {
      "attachment_id": "active_attachment_uuid",
      "sha256": "64 lowercase hexadecimal characters",
      "report": {}
    }
  }
}
```

Это сокращённая иллюстрация структуры, а не готовая карточка: в реальной передаче `geometry`, `report` и остальные поля заполнены; полный набор полей определяет JSON Schema. Заголовок `Idempotency-Key` совпадает с `idempotency_key`. Получатель дедуплицирует ключ и проверяет актуальность ревизии. Заблокированная карточка доступна для просмотра/экспорта, но не отправляется на подбор параметров.

## Полный отчёт STL

`stl_analysis.attachment_id` — активное вложение текущей ревизии; `sha256` — хеш исходных байтов STL. `report` — полный объект, возвращённый анализатором: геометрия, топология, проверки, сечения, выборочные измерения, единицы, предупреждения, ошибки, версии и служебные поля. Вложенные массивы, неизвестные будущие поля, `null`, `false` и числовые нули сохраняются без пересказа, фильтрации и усечения. Сравнение выполняется по значениям JSON: порядок ключей и формат записи чисел не являются частью контракта; JSONB может сериализовать отрицательный ноль как обычный ноль.

Сервер проверяет `report.file.sha256` и `report.units.input_unit` против активного файла и единиц задания. Кеш зависит от SHA-256, единиц, параметров и версии анализатора. `report.units` описывает применённый масштаб; `unknown` не превращается автоматически в миллиметры. После смены STL единицы снова требуют подтверждения. Текстовая правка может переиспользовать неизменившийся полный отчёт.

Поле `report.file.path` сохраняется как служебное значение анализатора. При повторном использовании кеша оно может относиться к первому вложению с такими же байтами; идентификатор активного вложения берётся из внешнего `attachment_id`. Этот путь не предоставляет файлового доступа получателю.

Частичный отчёт сохраняется полностью вместе с `partial_errors`, предупреждениями и областью применимости. Недоступные измерения остаются отсутствующими или `null`, не заменяются нулём. Если анализатор вообще не вернул структурированный отчёт либо активного STL нет, `stl_analysis = null`; причины и блокировки отражаются в `geometry.limitations` и правилах готовности. Сводная `geometry` остаётся для интерфейса и правил.

## Разделение модели и сервера

Qwen возвращает прежний контракт интерпретации: требования, источники, вопросы, конфликты, пожелания и ограничения. Полный отчёт не включается в контекст модели. После интерпретации сервер добавляет `stl_analysis`, `answers`, `resolutions`, актуальную ревизию и транспортную версию. Эти три серверных поля запрещены в ответе модели. Перед сохранением и передачей повторно проверяется актуальность задания: результат старой ревизии не становится текущим.

`answers` сохраняет фактические ответы, включая «Не знаю»; `resolutions` — явные решения по конфликтам. Вопрос с предложенным вариантом без выбора пользователя не считается отвеченным. Требования сохраняют источники и условия; объём сетки не становится расходом материала.

## Совместимость

Старые сохранённые карточки версии 1.0 продолжают читаться и не объявляются полными задним числом. Повтор обработки через `POST /api/v1/jobs/{id}/control/retry` с новым `request_id` создаёт следующую ревизию и карточку 1.1. Схема БД использует JSONB, поэтому добавление полей не требует изменения таблиц. Потребитель должен проверять `schema_version`, `revision`, готовность и допустимые действия.
